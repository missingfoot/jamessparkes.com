I kept reaching for the same handful of FFmpeg and ImageMagick commands to convert a batch of photos or clips into a different format, and got tired of retyping them. MediaConvert wraps that in a simple desktop window: drop files (or a whole folder) on it, pick a target format, hit convert.

## From one rejected batch to three groups

The first version treated a drop as a single all-or-nothing batch: mix an image in with a video, or include one file with an unrecognized extension, and the whole thing got rejected with an error. That's the kind of friction that makes a "just drop it in" tool stop feeling effortless.

The redesign splits a mixed drop into up to three independent sections, one each for video, image, and audio, every section with its own file table and target-format dropdown. Files with unsupported extensions are quietly dropped from the batch and reported as "N other files ignored" instead of blocking everything else.

## Keeping the UI honest while it converts

Conversion used to run in the same place as the interface, so the window would visibly freeze, and there was no sense of progress beyond a single row's status flickering. Moving the work into the background fixed both, with the window only hearing back when a file starts or finishes.

That drives each row's status and a running "Converting 2 / 5 audio files, 45 remaining"-style message, so the tables stay scrollable and responsive the whole time.

Even then, some batches still seemed to hang forever. The cause was FFmpeg sitting quietly waiting for keyboard input that would never come. Fixing that, and making any stuck or broken file show up as a normal failure with a Details button, mattered more than any feature: a converter you can't trust to finish isn't one you'll reach for.

Long batches also needed a way out. Pause finishes the current file and then waits, while Stop cancels it straight away, cleans up the half-written file and puts that row back to Ready.

Later I added optional PNG and JPEG optimising, plus an output size column showing how much each file grew or shrank. The optimiser is off by default, so a plain conversion still does exactly what you'd expect and the extra squeeze is something you choose.

Most of the interesting work here wasn't the conversion itself, ffmpeg and ImageMagick do the real work, it was the UI decisions around it: how to fail soft on a mixed batch instead of rejecting it outright, and how to keep a genuinely long-running operation from making the app feel broken while it runs.
