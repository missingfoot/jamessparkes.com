## The process

This project is one of a series of personal projects where I lean on AI-assisted IDEs like Cursor to accelerate development, while personally driving the project from problem definition through to release rather than just focusing on UX design:

<KVGroup>
  <KV term="Identify the problem" desc="Started with a real-world issue: Chrome's default tab management couldn't keep up with dozens of open tabs." />
  <KV term="Draft requirements" desc="Defined features and success criteria, using AI to generate early concepts and prototypes." />
  <KV term="Design & prototype" desc="Hand-coded the UI for the popup and options screens to keep the extension lightweight and fast." />
  <KV term="Develop the MVP" desc="Started with the two things I needed most, and set the project up so new features could be added one at a time." />
  <KV term="Test & iterate" desc="Used it as my own daily driver and gathered feedback from friends and family to refine functionality and UX." />
  <KV term="Document & reflect" desc="Kept a readme and roadmap so I could pick the project back up between AI sessions without losing context." />
</KVGroup>

## Development highlights

<KVGroup>
  <KV term="Incremental feature growth" desc="It started as two simple jobs: save a list of my open tabs, and reopen a pasted list. Grouping, closing duplicates, saved sessions and keyboard shortcuts came later, each added once I'd felt the need for it." />
  <KV term="Settings to turn things off" desc="As the feature list grew, I added a settings page to switch off the tools you don't use, so the popup only shows what you need." />
  <KV term="Firefox, too" desc="I later restructured the project to build for both Chrome and Firefox from one codebase, with the same features on each." />
  <KV term="Surviving huge sessions" desc="Restoring a big saved session could crash the browser by loading every tab at once. Now restored tabs only load when you click on them." />
</KVGroup>

## Result & impact

<KVGroup>
  <KV term="Greater efficiency" desc="My workflow and browser usage is less stressful and more efficient now, and multiple people have expressed interest in using it themselves." />
  <KV term="Ongoing evolution" desc="I've kept coming back to it for nearly two years, mostly when something gets in my way, which keeps it part of my daily routine." />
</KVGroup>

## Conclusion

Building Tab Tools gave me a view of the whole of product creation, from defining the problem through to shipping and gathering real user feedback. It reinforced how much AI-assisted development rewards clear documentation and requirements, much like good teamwork, and it's a workflow I've since carried back into professional projects.
